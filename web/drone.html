Your mission / 60-minute route

0–10: print Hello World. 10–25: practice ownership, byte decoding, and measurement storage. 25–33: read sensor registers and store decoded measurements. 33–38: flash P-only firmware. 38–48: implement I and D in 03-flight_controller/pid.rs. 48–55: reflash and compare. 55–60: recap.

error = target - altitude
integral = clamp(integral + error * dt, -3, 3)
correction = clamp(kp * error + ki * integral - kd * velocity, -8, 8)

Try kp = 3, ki = 1, kd = 2.5. Goal: every sample in the last 5 s has altitude error below 0.10 m and speed below 0.15 m/s. First complete the register driver in 03-flight_controller/controller.rs. Then use P-only to see steady error, then add D for damping and I to reject the sustained gust.

TF-01 easy datasheet / revision 1

A fictional 3.3 V board. All pins are logical teaching signals. This page does not emulate a CPU or program physical hardware.

PinDirectionMeaning
1 / 3V3PowerFake 3.3 V supply
2 / GNDPowerCommon reference
3 / LEDOutputOn while armed
4 / ALTInputSensor register 0x04, signed millimeters
5 / VELInputSensor register 0x08, signed mm/s, positive up
6–9 / M1–M4OutputsEqual motor duty, 0–100%, 50% balances gravity in this model
10 / BOOTInputEnter loader, stop playback

Sensor bank: 0x00 STATUS (READY bit 0), 0x02 SAMPLE_ID (u16), 0x04 ALT_MM (i32), 0x08 VEL_MM_S (i32). Multi-byte values use little endian. Firmware converts measurements by dividing by 1000.0 and stores them in self.latest before calling PID.

1000 control samples, dt = 0.02 s (50 Hz). Rust simulates 20 seconds ahead of time. The fake image stores the resulting telemetry. Flash validates and copies that image into this page's memory. Arm replays it. Changing gains requires rebuilding and reflashing. Reloading the page clears flash.

Model: acceleration = 20 × (duty − 0.5) − 0.6 × velocity + wind. Wind = −1 m/s² after 5 s. Floor at 0 m. This drone has only vertical motion, millimeter-quantized sensors, equal motor outputs, and no attitude or battery model.
